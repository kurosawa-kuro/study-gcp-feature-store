# 作業計画書 — study-gcp-feature-store

Vertex AI Feature Store の技術学習を目的としたサンプルプロジェクトを構築するための作業計画書。
仕様は [../README.md](../README.md)、リソースの流用元対応は [参照実装マッピング.md](参照実装マッピング.md) を参照。

## 0. 前提・方針（確定事項）

| 項目 | 決定 |
|---|---|
| 目的 | Feature Store の学習習得（BQ = 特徴量の実体・加工場所 / Feature Store = 管理・参照・配信レイヤー の責務分離を実機で理解） |
| IaC | **Terraform**（Feature Store 系は `google-beta` provider） |
| 実行形態 | **Cloud Run jobs**（seed 投入 / Feature View sync を job 化） |
| スコープ | **最小学習構成**。Composer / Dataform / skew monitoring は**採用しない** |
| スキーマ | 参照実装準拠（`rent/walk_min/age_years/area_m2/ctr/fav_rate/inquiry_rate`） |
| GCP project | `mlops-dev-a` |
| region | `asia-northeast1` |

> **意図的に避けるもの**: Cloud Composer、Dataform、Vector Search、KServe、Elasticsearch、feature skew 検証 SQL。これらは参照実装には在るが学習対象外。Feature Store の中核（FeatureGroup / Feature / FeatureView / Online Store / sync）だけに集中する。

## 1. 目的とゴール

README の学習ゴール:
- **BigQuery** = 特徴量データの実体・加工場所（実データ確認の中心）
- **Feature Store** = 特徴量の管理・参照・配信レイヤー
- **Feature Group** = BigQuery 特徴量テーブルを登録する単位
- **Feature View** = オンラインサービング / 同期のための参照単位

**完了像**: `terraform apply` → seed job → fv-sync job を経て、`gcloud ai` / `bq` CLI と GCP コンソール UI の双方で BigQuery データ・Feature Group・Feature View・Online Store を確認できる状態。

## 2. アーキテクチャ / データフロー

```
[Cloud Run job: seed]
   └─INSERT─▶ BigQuery  feature_mart.property_features_daily   (event_date partition / property_id cluster)
                              │
                              │ view: property_features_online_latest = 当日スライス (property_id + 7 features)
                              ▼
        Vertex AI Feature Group  property_features   (offline / schema 宣言 / Entity ID = property_id)
                              │
        Vertex AI Feature Online Store  mlops_dev_feature_store   (Optimized)
                 └─ Feature View  property_features ──BQ source materialize──▶ online serving (entity lookup)
                          ▲
[Cloud Run job: fv-sync] ─REST featureViews:sync + poll(finalStatus=OK)─┘
```

ポイント:
- **Feature Group は offline 用**（schema 宣言・Entity ID・Feature メタデータ管理）。online fetch の実体ではない。
- **Feature View が online serving の接続点**。BigQuery view (`property_features_online_latest`) を直接 materialize する（`feature_registry_source` 経由は sync 後も 404 になる既知事象があり、BQ source を直接指定する）。
- seed → sync の順序が重要（view が当日行を持ってから sync しないと Feature View が空になる）。

## 3. GCP リソース設計（Terraform）

`infra/terraform/` 配下に単一 environment（`mlops-dev-a` / `asia-northeast1`）。

| リソース | Terraform type | provider |
|---|---|---|
| BQ dataset `feature_mart` | `google_bigquery_dataset` | google |
| BQ table `property_features_daily` | `google_bigquery_table` | google |
| BQ view `property_features_online_latest` | `google_bigquery_table`(view) | google |
| Feature Group `property_features` | `google_vertex_ai_feature_group` | **google-beta** |
| Feature × 7 | `google_vertex_ai_feature_group_feature`(for_each) | **google-beta** |
| Feature Online Store `mlops_dev_feature_store` | `google_vertex_ai_feature_online_store`(`optimized {}`) | **google-beta** |
| Feature View `property_features` | `google_vertex_ai_feature_online_store_featureview` | **google-beta** |
| Artifact Registry repo | `google_artifact_registry_repository` | google |
| Service Account（job 実行用） | `google_service_account` + `google_project_iam_member` | google |
| Cloud Run job `seed` | `google_cloud_run_v2_job` | google |
| Cloud Run job `fv-sync` | `google_cloud_run_v2_job` | google |

IAM（job 用 SA に付与）:
- seed job SA: `roles/bigquery.dataEditor` + `roles/bigquery.jobUser`
- fv-sync job SA: `roles/aiplatform.user`
（学習用なので 1 SA に両ロール集約でも可。最小権限を学ぶなら job 別 SA に分離）

注意点（参照実装から踏襲）:
- Feature Group `big_query.big_query_source.input_uri = "bq://mlops-dev-a.feature_mart.property_features_daily"`、`entity_id_columns = ["property_id"]`。
- Online Store は `optimized {}` 種別。`UpdateFeatureOnlineStore` を拒否するため
  `lifecycle { ignore_changes = [optimized, dedicated_serving_endpoint, labels] }` を付ける。
- Feature View `big_query_source.uri = "bq://mlops-dev-a.feature_mart.property_features_online_latest"`、`entity_id_columns = ["property_id"]`、`sync_config.cron = "0 * * * *"`（hourly。手動 job sync と併用）。
- `enable_feature_online_store` 変数で Online Store + Feature View を gate（コスト bounding。必要時のみ apply）。

## 4. BigQuery スキーマ（参照実装準拠）

### `property_features_daily`（実体テーブル）
| 列 | 型 | mode | 備考 |
|---|---|---|---|
| `event_date` | DATE | REQUIRED | partition field |
| `feature_timestamp` | TIMESTAMP | NULLABLE | Feature Group BQ source の feature-time 列 |
| `property_id` | STRING | REQUIRED | **Entity ID** / clustering |
| `rent` | INT64 | NULLABLE | 家賃 |
| `walk_min` | INT64 | NULLABLE | 駅徒歩分 |
| `age_years` | INT64 | NULLABLE | 築年数 |
| `area_m2` | FLOAT64 | NULLABLE | 面積 |
| `ctr` | FLOAT64 | NULLABLE | クリック率 |
| `fav_rate` | FLOAT64 | NULLABLE | お気に入り率 |
| `inquiry_rate` | FLOAT64 | NULLABLE | 問い合わせ率 |
| `popularity_score` | FLOAT64 | NULLABLE | フォールバック人気度 |

- partition: `event_date`（DAY） / clustering: `property_id`

### `property_features_online_latest`（view = Feature View source）
```sql
SELECT property_id, rent, walk_min, age_years, area_m2, ctr, fav_rate, inquiry_rate
FROM `mlops-dev-a.feature_mart.property_features_daily`
WHERE event_date = CURRENT_DATE("Asia/Tokyo")
```
`event_date` / `feature_timestamp` を除外し当日 1 行/物件に絞る（Feature View の direct BQ source 制約に適合させるため）。

### Feature Group の Feature（7 個・全 `DOUBLE`）
`rent / walk_min / age_years / area_m2 / ctr / fav_rate / inquiry_rate`
（`property_id` は Entity ID なので Feature ではない。`event_date / feature_timestamp / popularity_score` は Feature 登録対象外）。

## 5. Cloud Run job 用アプリ（コンテナ）

`app/` に単一 image。`main.py` がコマンド引数（`seed` / `sync`）で分岐。

### `app/seed.py`（seed job）
- `google-cloud-bigquery` で 5 物件のサンプルを当日付で投入。
- べき等性: `property_features_daily` を `CREATE OR REPLACE TABLE` ではなく、当日分 `DELETE` + `INSERT`、または `MERGE` で再実行安全に。
- サンプル物件（参照 seed_minimal.py 流用）:
  | property_id | rent | walk_min | age_years | area_m2 | ctr | fav_rate | inquiry_rate | popularity_score |
  |---|---|---|---|---|---|---|---|---|
  | p001 | 120000 | 5 | 8 | 35.0 | 0.05 | 0.10 | 0.02 | 0.5 |
  | p002 | 95000 | 3 | 12 | 22.0 | 0.04 | 0.08 | 0.01 | 0.4 |
  | p003 | 165000 | 7 | 5 | 50.0 | 0.06 | 0.12 | 0.03 | 0.6 |
  | p004 | 110000 | 4 | 15 | 25.0 | 0.03 | 0.07 | 0.01 | 0.35 |
  | p005 | 140000 | 6 | 10 | 42.0 | 0.05 | 0.11 | 0.02 | 0.55 |

### `app/sync.py`（fv-sync job）
- 参照 `feature_view_sync.py` の REST polling を移植:
  1. POST `https://{REGION}-aiplatform.googleapis.com/v1beta1/projects/{PROJECT}/locations/{REGION}/featureOnlineStores/{STORE}/featureViews/{VIEW}:sync`
  2. GET `.../featureViewSyncs?pageSize=5` を `finalStatus.code == 0` かつ `runTime.endTime` が立つまで poll（timeout 1800s / poll 15s）
- **IDs は terraform output 依存をやめ、Cloud Run job の env から取得**:
  `PROJECT_ID` / `REGION` / `FEATURE_ONLINE_STORE_ID` / `FEATURE_VIEW_ID`
- 認証: Cloud Run job の SA で metadata server から access token を取得（`google.auth` でも urllib + metadata でも可）。

### `infra/Dockerfile`
- Python 3.12 slim ベース、uv で依存解決、`ENTRYPOINT ["python", "-m", "app.main"]`。
- Cloud Run job 側 `args` で `["seed"]` / `["sync"]` を指定。

依存（`pyproject.toml`）: `google-cloud-bigquery`, `google-cloud-aiplatform`（sync は urllib + `google.auth` でも可）。

## 7. フェーズ別作業手順

### Phase 0 — 足場
- `cd study-gcp-feature-store && git init`（ワークスペース root は git 管理外なのでこの project 直下で init）。
- `pyproject.toml`（uv / python 3.12）、`.gitignore`（`.terraform/`, `*.tfstate*`, `__pycache__`, `.venv` 等）、`Makefile` 雛形。
- `CLAUDE.md` の「現状」節を実装着手に合わせて更新。

### Phase 1 — BigQuery（Terraform）
- dataset `feature_mart` + `property_features_daily` + `property_features_online_latest`(view) を `terraform apply`。
- 確認: `bq show --schema mlops-dev-a:feature_mart.property_features_daily`。

### Phase 2 — Feature Store（Terraform）
- Feature Group + Feature × 7 + Online Store(`optimized`) + Feature View を apply（`google-beta`）。
- `enable_feature_online_store = true` で Online Store/View を含める。
- Online Store のプロビジョニングは数分かかる点に留意。

### Phase 3 — コンテナ + Cloud Run jobs
- `app/` 実装（seed / sync）。
- **image 存在順序の注意**: Cloud Run job は image が存在しないと作成できない。
  1. AR repo を先に apply（`terraform apply -target=google_artifact_registry_repository.repo`）
  2. `docker buildx build --platform linux/amd64 -t {region}-docker.pkg.dev/mlops-dev-a/{repo}/feature-store-job:latest --push .`
  3. 残りを `terraform apply`（Cloud Run jobs 含む）
- Makefile の `build-push` → `tf-apply` 順でこれを担保。

### Phase 4 — 実行
```bash
gcloud run jobs execute seed    --project=mlops-dev-a --region=asia-northeast1 --wait
gcloud run jobs execute fv-sync --project=mlops-dev-a --region=asia-northeast1 --wait
```
seed → fv-sync の順を厳守（view が当日行を持ってから sync）。

## 8. CLI 検証手順（gcloud / bq）

```bash
# --- BigQuery（実データ確認の中心）---
bq ls --project_id=mlops-dev-a feature_mart
bq show --project_id=mlops-dev-a feature_mart.property_features_daily
bq query --use_legacy_sql=false \
  'SELECT * FROM `mlops-dev-a.feature_mart.property_features_daily` LIMIT 5'
bq query --use_legacy_sql=false \
  'SELECT * FROM `mlops-dev-a.feature_mart.property_features_online_latest`'

# --- Feature Group ---
gcloud ai feature-groups list \
  --project=mlops-dev-a --location=asia-northeast1
gcloud ai feature-groups describe property_features \
  --project=mlops-dev-a --location=asia-northeast1
gcloud ai feature-groups features list \
  --feature-group=property_features \
  --project=mlops-dev-a --location=asia-northeast1

# --- Online Store + Feature View + sync 履歴 ---
gcloud ai feature-online-stores list \
  --project=mlops-dev-a --location=asia-northeast1
gcloud ai feature-online-stores describe mlops_dev_feature_store \
  --project=mlops-dev-a --location=asia-northeast1
gcloud ai feature-online-stores feature-views list \
  --feature-online-store=mlops_dev_feature_store \
  --project=mlops-dev-a --location=asia-northeast1
gcloud ai feature-online-stores feature-views syncs list \
  --feature-online-store=mlops_dev_feature_store \
  --feature-view=property_features \
  --project=mlops-dev-a --location=asia-northeast1 --limit=5

# --- Cloud Run jobs ---
gcloud run jobs list --project=mlops-dev-a --region=asia-northeast1
gcloud run jobs executions list --job=seed \
  --project=mlops-dev-a --region=asia-northeast1
```

> gcloud のサブコマンド表記（`features list` / `feature-views` 等）は SDK バージョンで揺れることがあるため、実機で `gcloud ai feature-groups --help` 等を突き合わせて確定版に直す。

## 11. コスト / teardown

- **Optimized Online Store はノード常駐 + 読み込み課金**。学習が済んだら必ず撤去する。
- `make destroy`（= `terraform destroy`）で全リソース削除。BQ table は `deletion_protection` を学習用に `false` にして destroy 可能にする。
- 一時的にコストだけ止めたい場合は `enable_feature_online_store = false` で apply（Online Store + Feature View のみ削除、BQ と Feature Group は残す）。
