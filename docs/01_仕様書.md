# 01 仕様書 — study-gcp-feature-store

Vertex AI Feature Store の技術学習を目的とした不動産検索向けサンプルプロジェクトの仕様。
実装の詳細・流用元・検証結果は [02_実装カタログ.md](02_実装カタログ.md)、構築・運用手順は [03_運用.md](03_運用.md)。

## 1. 目的・学習ゴール

不動産物件のサンプルデータを題材に、BigQuery に蓄積した特徴量を Vertex AI Feature Store に登録し、CLI と GCP コンソール UI の両方から確認・検証する。以下の責務分離を実機で理解する。

- **BigQuery** = 特徴量データの実体・加工場所（実データ確認の中心）
- **Feature Store** = 特徴量の管理・参照・配信レイヤー
- **Feature Group** = BigQuery 特徴量テーブルを登録する単位
- **Feature View** = オンラインサービング / 同期のための参照単位
- **Online Store** = Feature View の同期先（オンライン配信）

## 2. 確定方針

| 項目 | 決定 |
|---|---|
| IaC | **Terraform**（Feature Store 系は `google-beta` provider） |
| 実行形態 | **Cloud Run jobs**（seed / sync / seed-raw / build-features / export を job 化） |
| スキーマ | 参照実装準拠（`rent/walk_min/age_years/area_m2/ctr/fav_rate/inquiry_rate`） |
| GCP project / region | `mlops-dev-a` / `asia-northeast1` |

## 3. アーキテクチャ / データフロー

```
[アドオン2] raw dataset (property_master / search_log / pv_log / favorite_log)
      ↓ build-features: BQ SQL (JOIN / 28日集計 / SAFE_DIVIDE 欠損補完 / feature_timestamp)
BigQuery  feature_mart.property_features_daily   (property_id = Entity ID)
      │   ↑ seed (固定5件の quick 路線) も併存
      │   property_features_online_latest (view = 当日スライス)
      ▼
Vertex AI Feature Store
  ├─ Feature Group  property_features    … BQ テーブルを登録 (offline / schema 宣言)
  ├─ Feature × 7                          … 特徴量カラムを Feature 登録
  ├─ Feature View   property_features    … online serving の接続点 (BQ source 直接 materialize)
  └─ Online Store   mlops_dev_feature_store (Optimized) … sync 先
      ▲ sync (REST :sync + finalStatus=OK まで polling)
      │
[アドオン1] export: 特徴量取得 (bq / online) → CSV → GCS → 簡易 downstream 確認
```

設計上の要点:
- **Feature Group は offline 用**（schema 宣言・Entity ID・Feature メタデータ）。online fetch の実体ではない。
- **Feature View が online serving の接続点**。`property_features_online_latest` view を直接 materialize する（`feature_registry_source` 経由は sync 後も 404 になる既知事象のため BQ source を直接指定）。
- データを投入してから sync する順序が重要（view が当日行を持ってから sync しないと Feature View が空になる）。

## 4. スキーマ（参照実装準拠）

### `feature_mart.property_features_daily`（実体テーブル）
| 列 | 型 | mode | 区分 |
|---|---|---|---|
| `event_date` | DATE | REQUIRED | partition |
| `feature_timestamp` | TIMESTAMP | NULLABLE | feature-time 列 |
| `property_id` | STRING | REQUIRED | **Entity ID** / clustering |
| `rent` | INT64 | NULLABLE | Feature（家賃） |
| `walk_min` | INT64 | NULLABLE | Feature（駅徒歩分） |
| `age_years` | INT64 | NULLABLE | Feature（築年数） |
| `area_m2` | FLOAT64 | NULLABLE | Feature（面積） |
| `ctr` | FLOAT64 | NULLABLE | Feature（クリック率） |
| `fav_rate` | FLOAT64 | NULLABLE | Feature（お気に入り率） |
| `inquiry_rate` | FLOAT64 | NULLABLE | Feature（問い合わせ率） |
| `popularity_score` | FLOAT64 | NULLABLE | フォールバック人気度 |

Feature Group に登録する Feature は 7 個（`rent`/`walk_min`/`age_years`/`area_m2`/`ctr`/`fav_rate`/`inquiry_rate`）。`property_id` は Entity ID、`event_date`/`feature_timestamp`/`popularity_score` は Feature 登録対象外。

### `property_features_online_latest`（view = Feature View source）
```sql
SELECT property_id, rent, walk_min, age_years, area_m2, ctr, fav_rate, inquiry_rate
FROM `mlops-dev-a.feature_mart.property_features_daily`
WHERE event_date = CURRENT_DATE("Asia/Tokyo")
```
`event_date`/`feature_timestamp` を除外し当日 1 行/物件に絞る（Feature View の direct BQ source 制約に適合）。

> 初版で例示した列（`area_sqm` / `station_distance_minutes` / `floor` / `has_auto_lock` 等）は採用していない。稼働中の参照実装 [study-gcp-search-mlops-gke](../../study-gcp-search-mlops-gke/) との整合を優先して上記スキーマを採用した。

## 5. 検証内容（4 段階）

1. **BigQuery**: dataset / 特徴量テーブル / view 作成、サンプル投入、SQL で確認
2. **Feature Store**: Feature Group（`property_id`=Entity ID）/ Feature×7 / Feature View / Online Store 同期
3. **CLI 検証**: `bq` + Vertex AI REST（`gcloud ai feature-*` は SDK に無い）/ online `fetchFeatureValues`
4. **GCP UI 検証**: コンソール（BigQuery / Vertex AI Feature Store / Knowledge Catalog）

## 6. アドオン仕様

### アドオン1 — Feature Store 後段（CSV / GCS 出力）
Feature Store への登録・同期で終わらせず、**Feature Store から特徴量を取得し CSV / GCS へ出力する後段処理**を追加し、出力 CSV を読み戻して簡易 downstream 利用を確認する。

```
Feature Store → Feature View sync → 特徴量取得 → CSV出力 / GCS出力 → 簡易 downstream 利用確認
```

取得元は 2 経路（学習目的で両対応）: **bq**（`property_features_online_latest` を直接 query）/ **online**（Online Store の `fetchFeatureValues` を entity ごと）。

**やらない（禁止）**: モデル学習 / Endpoint 作成 / 推論 API。

### アドオン2 — BigQuery 内特徴量生成パイプライン
複数の raw / master テーブルから **BigQuery 内の SQL だけで Feature Store 投入用の特徴量テーブルを生成する**。データ収集・結合・集計・欠損補完・期間集計・`feature_timestamp` 付与を検証する。

```
BigQuery raw / master tables → BQ SQL (JOIN / 集計 / 欠損補完 / 期間集計 / feature_timestamp 付与)
  → BigQuery feature table (property_features_daily) → Vertex AI Feature Store
```

raw テーブル（不動産ドメイン）: `property_master` / `search_log`（impression）/ `pv_log`（click 相当）/ `favorite_log`（favorite・inquiry）。既存の固定投入 `seed`（quick 路線）と**併存**する。

**やらない（対象外）**: 外部 DB 連携 / モデル学習 / **Dataform**（plain BQ SQL で行う）。

## 7. スコープ外（意図的に採用しない）

学習対象を Feature Store 中核に絞るため、以下は採用しない:
Cloud Composer / Dataform / Vector Search / KServe / Elasticsearch / skew monitoring / モデル学習 / Endpoint / 推論 API / 外部 DB 連携 / 認証付き REST API / Web UI。
