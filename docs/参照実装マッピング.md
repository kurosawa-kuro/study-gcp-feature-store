# 参照実装マッピング — study-gcp-feature-store

本プロジェクトの各リソース/コードが、稼働中の参照実装
[study-gcp-search-mlops-gke/](../../study-gcp-search-mlops-gke/)（`mlops-dev-a` で稼働）の
どのファイルに対応するかの対応表。流用時の差分も明記する。

> 参照実装は Composer + Vector Search + KServe + LightGBM を含むフル MLOps だが、
> 本プロジェクトは **Feature Store の中核だけ**を切り出した最小学習構成。
> 流用するのは「BigQuery 特徴量テーブル + Feature Group/View/Online Store + sync」の部分のみ。

## 主要な設計差分（参照 → 本プロジェクト）

| 観点 | 参照実装 | 本プロジェクト | 理由 |
|---|---|---|---|
| orchestration | Cloud Composer `daily_feature_refresh` DAG | Cloud Run jobs（手動 execute） | Composer は重い。学習に不要 |
| feature 計算 | Dataform `property_features_daily.sqlx` | seed job が固定サンプルを直接 INSERT | Dataform は学習対象外。実データ加工より Feature Store 操作の理解が目的 |
| sync の ID 解決 | terraform output -json | Cloud Run job の env（`FEATURE_ONLINE_STORE_ID` 等） | job 実行時に terraform を呼べないため env 注入に変更 |
| 認証 | gcloud auth print-access-token | Cloud Run job SA + metadata server | コンテナ内に gcloud が無いため |
| 周辺技術 | Vector Search / KServe / ES / LightGBM 同梱 | なし | Feature Store 単体学習にスコープを絞る |
| CLI 検証 | docs に `gcloud ai feature-groups` 等を記載 | **REST API (curl)** = `scripts/verify_cli.sh` | gcloud SDK 563.x に `gcloud ai feature-*` が存在しないことが実機で判明したため REST に変更 |
