## 1. 目的・スコープ

Vertex AI Feature Store への登録・同期で終わらせず、**Feature Store から特徴量を取得し CSV / GCS へ出力する後段処理**を追加する。最後に取り出した CSV を読み戻して簡易 downstream 利用を確認する。

```
Feature Store → Feature View sync → 特徴量取得 → CSV出力 / GCS出力 → 簡易 downstream 利用確認
```

**やらない（spec 禁止事項）**:
- モデル学習しない
- Endpoint は作らない
- 推論 API は作らない

## 2. アーキテクチャ / データフロー

```
                            ┌─(FETCH_SOURCE=bq)──  feature_mart.property_features_online_latest (当日スライス)
 特徴量取得 (app/export.py) ─┤
                            └─(FETCH_SOURCE=online)─ Online Store : fetchFeatureValues を entity ごとに呼ぶ
        ↓
 CSV を /tmp に書き出し  (stdlib csv)
        ↓
 GCS へ upload   gs://<bucket>/<EXPORT_PREFIX>/property_features_YYYYMMDD.csv   (google-cloud-storage)
        ↓
 簡易 downstream 利用確認 : GCS から読み戻し → 行数 + 先頭数件を print
```

取得元を 2 経路サポートする学習意図:
- **bq**（offline / 実体）: 常に取得可・低コスト。Feature Store の source である BigQuery を直接読む。
- **online**（serving）: `fetchFeatureValues` で entity 単位に Online Store から引く。spec の flow（sync → 取得）に忠実だが Online Store 稼働が前提（課金）。

## 3. 追加リソース（Terraform / `infra/terraform/main.tf`）

| リソース | type | 設定 |
|---|---|---|
| GCS bucket | `google_storage_bucket` | name = `${var.project_id}-feature-export-${var.region}`、`location=var.region`、`uniform_bucket_level_access=true`、`force_destroy=true`（学習用、destroy 可）、`lifecycle_rule { condition{age=14} action{type="Delete"} }` |
| bucket IAM | `google_storage_bucket_iam_member` | bucket scope で job_sa に `roles/storage.objectAdmin` |
| Cloud Run job `feature-export` | `google_cloud_run_v2_job` | args `["export"]`、`deletion_protection=false`、timeout `600s` |

`feature-export` job の env:
```
PROJECT_ID, REGION
FETCH_SOURCE              # "bq" | "online"  (default "bq")
EXPORT_BUCKET            # = google_storage_bucket.export.name
EXPORT_PREFIX            # default "exports"
FEATURE_ONLINE_STORE_ID  # online 時のみ使用
FEATURE_VIEW_ID          # online 時のみ使用
```

新規変数: `bucket 名は project_id 依存のため変数不要（local で組み立て）`。`enable_feature_online_store=false` の場合 online モードは使えない旨を job 説明に明記。

## 4. アプリ実装

### `app/export.py`（新規）
- env 読み取り: `FETCH_SOURCE`(default `bq`) / `EXPORT_BUCKET`(必須) / `EXPORT_PREFIX`(default `exports`) / 任意 `ENTITY_KEYS`
- 取得:
  - **bq モード**: `bigquery.Client().query("SELECT property_id, rent, walk_min, age_years, area_m2, ctr, fav_rate, inquiry_rate FROM \`{p}.feature_mart.property_features_online_latest\` ORDER BY property_id")` → 行リスト
  - **online モード**:
    1. entity key 一覧 = `ENTITY_KEYS`（カンマ区切り）か、無ければ BQ `SELECT DISTINCT property_id FROM ...online_latest`
    2. Online Store の `publicEndpointDomainName` を REST GET（`{region}-aiplatform.googleapis.com/v1/projects/{p}/locations/{r}/featureOnlineStores/{store}`）で解決（`scripts/verify_cli.sh` と同パターン）
    3. 各 key に `:fetchFeatureValues` POST（`{"data_key":{"key":key}}`）→ `keyValues.features` を列に整形
- CSV: stdlib `csv.writer` で `/tmp/property_features_YYYYMMDD.csv` に書く（ヘッダ = property_id + 7 features）。**pandas は使わない**（image を軽く保つ）
- GCS upload: `google.cloud.storage.Client().bucket(EXPORT_BUCKET).blob(f"{EXPORT_PREFIX}/property_features_{YYYYMMDD}.csv").upload_from_filename(...)`（参照 `ml/registry/artifact_store.py` のパターン）
- **簡易 downstream 利用確認**: アップロードした blob を `download_as_text()` で読み戻し、`csv.DictReader` で行数と先頭 3 件を print（「取り出した特徴量がそのまま downstream で読める」ことの確認）
- 認証: Cloud Run job SA。`google.auth.default(scopes=[...cloud-platform])` で token（`app/sync.py` の `_access_token` を共通化して流用）

### `app/main.py`（変更）
コマンド分岐に `export` を追加。3 コマンド以上になるので dispatch table 化を提案:
```python
COMMANDS = {"seed": seed.run, "sync": sync.run, "export": export.run}
```

## 5. 依存・Makefile・Dockerfile

- `pyproject.toml` dependencies に `google-cloud-storage>=2.18` 追加
- `infra/Dockerfile` の `uv pip install` に `google-cloud-storage>=2.18` 追加
- `Makefile`:
  ```make
  export:      ## CSV/GCS 出力 job 実行
  	gcloud run jobs execute feature-export --project=$(PROJECT_ID) --region=$(REGION) --wait
  verify-export: ## GCS の出力を確認
  	gcloud storage ls gs://$(PROJECT_ID)-feature-export-$(REGION)/exports/
  	gcloud storage cat $$(gcloud storage ls gs://$(PROJECT_ID)-feature-export-$(REGION)/exports/ | tail -1) | head
  ```

## 6. 実行フロー

```
make deploy                       # GCS bucket + feature-export job 含めて apply (build-push 順は既存どおり)
make seed   (または アドオン2)     # 特徴量テーブルにデータ
make sync                         # online モードを使う場合は必須
make export                       # FETCH_SOURCE は job env (既定 bq)。online は env 上書きで
make verify-export                # GCS object + CSV head 確認
```

online モードで実行する場合は `gcloud run jobs execute feature-export --update-env-vars FETCH_SOURCE=online --wait` のように上書き。
