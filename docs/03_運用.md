# 03 運用 — study-gcp-feature-store

構築・実行・検証・撤去の手順。仕様は [01_仕様書.md](01_仕様書.md)、実装の詳細は [02_実装カタログ.md](02_実装カタログ.md)。

## 1. コマンド早見（Makefile）

```bash
make tf-init          # terraform init
make check            # ruff + terraform fmt -check + validate（GCP に触れない）
make deploy           # AR apply → image build/push → 残り apply（image 存在順序を担保）
make seed             # Cloud Run job: 固定5件を property_features_daily へ（quick 路線）
make sync             # Cloud Run job: Feature View sync + 待機
make verify-cli       # bq + Vertex AI REST でリソース確認
make destroy          # 全リソース撤去（課金停止）

# アドオン2（raw → SQL 集計で特徴量生成）
make seed-raw         # raw 4 テーブルへサンプル投入
make build-features   # raw → property_features_daily を SQL 生成
# アドオン1（Feature Store → CSV/GCS 出力）
make export           # 特徴量取得 → CSV → GCS（既定 FETCH_SOURCE=bq）
make verify-export    # GCS の出力 CSV を確認
```

## 2. 標準フロー / 合成フロー

```
make tf-init
make deploy
# quick 路線:           make seed → make sync
# アドオン2 現実路線:    make seed-raw → make build-features → make sync
make verify-cli
make export → make verify-export      # アドオン1
make destroy
```

合成フロー（前段アドオン2 → 本体 → 後段アドオン1）:
`make deploy → seed-raw → build-features → sync → export → verify-export → destroy`

## 3. デプロイ手順（image 存在順序）

Cloud Run job は image が存在しないと作成できない。`make deploy` が以下を順に実行:
1. `tf-apply-ar` — Artifact Registry repo（+ API 有効化）を先に apply
2. `build-push` — `docker buildx build --platform linux/amd64 … --push`
3. `tf-apply` — 残り全リソース（BQ / Feature Store / GCS / raw / Cloud Run jobs）

## 4. 実行と検証

### BigQuery / Feature Store（本体）
```bash
make seed-raw && make build-features   # または make seed
make sync                              # ⚠ 初回 約19〜21分（§6）
make verify-cli                        # bq 2 クエリ + REST（Feature Group / Online Store / Feature View / sync 履歴 / online fetch）/ Cloud Run jobs
```
`verify-cli` の中身は [scripts/verify_cli.sh](../scripts/verify_cli.sh)。`gcloud ai feature-*` は SDK に無いため Feature Store 系は REST（`gcloud auth print-access-token` + curl）。

### アドオン1（CSV/GCS export）
```bash
make export            # 既定 bq モード
make verify-export     # gcloud storage ls + CSV head
# online モード（sync 完了から数分おいて実行）:
gcloud run jobs execute feature-export --project=mlops-dev-a --region=asia-northeast1 \
  --update-env-vars "^@^FETCH_SOURCE=online" --wait
# 特定 entity だけ（env 値にカンマを含むので ^@^ 区切り必須）:
#   --update-env-vars "^@^FETCH_SOURCE=online@ENTITY_KEYS=p001,p003"
```

## 5. 実測所要時間（2026-05-20 / mlops-dev-a）

| フェーズ | コマンド | 実測 wall |
|---|---|---|
| AR repo + API 有効化 | `make tf-apply-ar` | 約 30〜60s |
| image build & push | `make build-push` | 約 65s |
| 全スタック apply | `make tf-apply` | 約 40s（Online Store/View 各 ~11s、SA ~15s、IAM 各 ~10s、Cloud Run job 各 ~11s） |
| seed / seed-raw / build-features / export | 各 job | 約 25〜30s |
| **fv-sync（初回）** | `make sync` | **約 19〜21 分** |
| fv-sync（2 回目以降） | `make sync` | 約 3〜4 分 |

初回 E2E 合計 ≒ **約 24〜25 分**（fv-sync 初回が支配的）。日常の更新サイクル（seed/build-features → sync → export）は **約 4 分**。

## 6. 注意事項（実機で判明した挙動）

- ⚠️ **初回 `make sync` は約19〜21分**。Optimized Online Store の serving ノード（minReplica=2）初期プロビジョニング + 初回 materialize のため。2 回目以降は数分。`app/feature_store/sync.py` の `TIMEOUT_SEC=1800` はこれを見込んだ値。
- ⚠️ **sync 完了直後の数分間、`fetchFeatureValues` が全 entity 404**（serving ノードへの伝播遅延）。**sync 完了 ≠ online 取得可**。online 一括取得は数分おいてから。`app/feature_store/export.py` は 404 を warn+skip。未 materialize entity（全特徴量 NULL の行）も 404 になりうる。
- ⚠️ **`gcloud ai feature-*` は SDK 563.x に存在しない**。Feature Store の確認は Vertex AI REST API を使う（`make verify-cli`）。
- ⚠️ online モードを `gcloud run jobs execute --update-env-vars` で渡すとき、env 値にカンマを含む場合は **カスタム区切り `^@^`** が必須（例: `ENTITY_KEYS=p001,p003`）。
- seed/build-features → sync の順序を守る（view が当日行を持ってから sync）。

## 7. コスト / teardown

- **Optimized Online Store はノード常駐 + 読み込み課金**、GCS bucket も保持コスト。学習が済んだら撤去する。
- `make destroy`（= `terraform destroy`）で全リソース削除。
  - BQ table / raw table は `enable_deletion_protection=false`（学習用既定）で destroy 可能。
  - **全 Cloud Run job に `deletion_protection=false` を明示済み**（provider 6.x のデフォルトは `true` で、無いと `cannot destroy job without setting deletion_protection=false` で失敗する）。
  - GCS bucket は `force_destroy=true` で中の object ごと削除。
- 一時的にコストだけ止める場合は `enable_feature_online_store=false` で apply（Online Store + Feature View のみ削除、BQ / Feature Group は残す）。
- **撤去実績（2026-05-20）**: `make destroy` で全リソース削除、terraform state 空 / Online Store `{}` / dataset 無し / jobs 無しを確認、課金停止。
