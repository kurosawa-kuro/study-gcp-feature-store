## 2. Terraform リソース

`infra/terraform/`（単一 environment、`mlops-dev-a` / `asia-northeast1`）。Feature Store 系は **`google-beta`** provider。

| リソース | type | 備考 |
|---|---|---|
| BQ dataset `feature_mart` | `google_bigquery_dataset` | |
| BQ table `property_features_daily` | `google_bigquery_table` | event_date partition / property_id cluster |
| BQ view `property_features_online_latest` | `google_bigquery_table`(view) | 当日スライス |
| Feature Group `property_features` | `google_vertex_ai_feature_group` | `entity_id_columns=["property_id"]`、BQ source 直接 |
| Feature × 7 | `google_vertex_ai_feature_group_feature`(for_each) | rent/walk_min/age_years/area_m2/ctr/fav_rate/inquiry_rate |
| Online Store `mlops_dev_feature_store` | `google_vertex_ai_feature_online_store`(`optimized {}`) | `lifecycle.ignore_changes=[optimized, dedicated_serving_endpoint, labels]` |
| Feature View `property_features` | `google_vertex_ai_feature_online_store_featureview` | BQ source 直接 materialize、`sync_config.cron="0 * * * *"` |
| Artifact Registry repo `feature-store` | `google_artifact_registry_repository` | Cloud Run image 置き場 |
| Service Account `feature-store-job` + IAM | `google_service_account` + `google_project_iam_member` | `bigquery.dataEditor` + `bigquery.jobUser` + `aiplatform.user` |
| **[アドオン2]** dataset `raw` + 4 テーブル | `google_bigquery_dataset` / `google_bigquery_table` | property_master / search_log / pv_log / favorite_log（log 系は timestamp partition + property_id cluster） |
| **[アドオン1]** GCS bucket `${project}-feature-export-${region}` + IAM | `google_storage_bucket` + `google_storage_bucket_iam_member` | `force_destroy=true`、14日 lifecycle、job_sa に `storage.objectAdmin` |
| Cloud Run jobs `seed` / `fv-sync` / `seed-raw` / `build-features` / `feature-export` | `google_cloud_run_v2_job` | 単一イメージ + args 分岐。**全 job `deletion_protection=false`** |

gate 変数: `enable_feature_online_store`（Online Store + View をコスト bounding で gate）/ `enable_deletion_protection`（BQ table、学習用 false）/ `raw_dataset_id`。

## 3. app（Cloud Run job アプリ）

`main.py` の dispatch table（`seed`/`sync`/`seed-raw`/`build-features`/`export`）で単一イメージを分岐。

| コマンド | モジュール | 機能 |
|---|---|---|
| `seed` | `app/data/seed.py` | 固定5件を当日付で `DELETE`+`INSERT`（冪等） |
| `sync` | `app/feature_store/sync.py` | REST `:sync` POST → `featureViewSyncs` を finalStatus=OK まで polling。IDs は env、auth は `app/common/auth.py`（job SA） |
| `seed-raw` | `app/data/seed_raw.py` | raw 4 テーブルへ `TRUNCATE`+`INSERT`。impression/pv/favorite/inquiry を物件ごと件数変えて `GENERATE_ARRAY` 展開。p006 は行動ログ無し |
| `build-features` | `app/data/build_features.py` + `app/data/sql/build_features.sql` | 28日 window JOIN / `SAFE_DIVIDE` 欠損補完 / `feature_timestamp` 付与で `property_features_daily` 生成（`DELETE`+`INSERT WITH … SELECT`） |
| `export` | `app/feature_store/export.py` | bq（view query）/ online（fetchFeatureValues）で取得 → stdlib csv → GCS upload → 読み戻し downstream 確認。online は 404 を warn+skip |

### 主要な設計差分（参照 → 本プロジェクト）
| 観点 | 参照実装 | 本プロジェクト | 理由 |
|---|---|---|---|
| orchestration | Cloud Composer DAG | Cloud Run jobs（手動 execute） | Composer は重い |
| feature 計算 | Dataform | アドオン2 の plain BQ SQL / quick は固定投入 | Dataform 不採用 |
| sync の ID 解決 | terraform output | Cloud Run job env | job 内で terraform を呼べない |
| 認証 | gcloud auth print-access-token | job SA + metadata server（`google.auth`） | コンテナに gcloud 無し |
| CLI 検証 | `gcloud ai feature-*`（doc 記載） | bq + Vertex AI REST（`scripts/verify_cli.sh`） | SDK 563.x に該当コマンド無し |

## 6. 設計判断・既知の挙動

- **raw テーブルは Terraform 管理 schema + `TRUNCATE`/`INSERT`**（`CREATE OR REPLACE TABLE` は Terraform 管理を上書きして drift するため不採用）。
- **`build-features` の出力 schema は既存 `property_features_daily` と完全一致** → Feature Group / Feature View は無変更。
- export の CSV は **stdlib `csv`**（pandas を入れず image を軽量維持）。
- ⚠️ **gcloud SDK 563.x に `gcloud ai feature-*` が無い** → Feature Store の CLI 操作・検証は Vertex AI REST API（`scripts/verify_cli.sh`）。
- ⚠️ **Feature View sync 完了直後は数分間 `fetchFeatureValues` が全 entity 404**（serving ノードへの伝播遅延）。online 一括取得は数分おく / 404 を skip。
- ⚠️ **`google_cloud_run_v2_job` の `deletion_protection` デフォルトは `true`** → 全 job に `deletion_protection=false` を明示（無いと destroy 失敗）。
- ⚠️ 未 materialize の entity（全特徴量 NULL の行など）も online fetch で 404 になりうる。
